Privacy Policy for SecureShield

Last updated: October 19, 2026

This Privacy Policy describes how SecureShield, developed and published by HI Digital Studios, accesses, uses, stores, and protects information while providing Android security and device-protection features.

Privacy Summary:

SecureShield is designed primarily as an on-device security application. Security scans and analysis are performed locally on the user's Android device. SecureShield does not automatically upload personal data, SMS messages, installed-app information, scanned files, photographs, security reports, App Lock credentials, or network scan information to a SecureShield server or to third-party servers. SecureShield does not sell user data.

1. Information SecureShield May Access

Depending on the Android version, device capabilities, permissions granted by the user, and features enabled by the user, SecureShield may access the following information locally on the device.

Installed Applications and Package Information

SecureShield may inspect installed applications in order to provide app-security and risk-analysis features.

This may include:

  • Application name
  • Package name
  • Application version
  • Android SDK information
  • Application installation source
  • Requested permissions
  • Application signing certificate information or hashes
  • Application installation, update, or removal events
  • Whether an application has certain security-sensitive capabilities

This information is used locally to identify security-relevant conditions, suspicious combinations of permissions, application changes, sideloaded applications, signer changes, and other security indicators.

Device Security Information

SecureShield may inspect locally available Android security information, including:

  • Android version and security patch information
  • Developer Options status
  • USB debugging status
  • Wireless debugging status where available
  • Device integrity and possible root indicators
  • Secure screen-lock status
  • Biometric capability status
  • Accessibility-service status
  • Overlay permission status
  • Device administrator status
  • Notification-access status
  • Usage Access status
  • Unknown-app installation settings
  • Storage and device-health information
  • Location/GPS and related security-state information where supported

SecureShield uses this information to provide security recommendations and does not use it to build advertising profiles.

SMS Messages

If the user grants SMS permission, SecureShield may access SMS message content for the purpose of detecting possible phishing, scam, or suspicious message indicators.

SMS analysis is performed locally on the device. SecureShield does not automatically upload SMS contents to a SecureShield server or third party.

Users may deny or revoke SMS permission using Android Settings. Features that depend on SMS access may then become unavailable.

Files, APKs, and Archives

When file-scanning features are used, SecureShield may inspect files that the app is permitted to access.

This may include:

  • File name and file type
  • File size and metadata
  • SHA-256 or similar cryptographic hashes
  • APK package information
  • APK permissions and signing information
  • ZIP, APKS, or XAPK archive structure
  • Potentially risky file extensions or characteristics

File analysis is intended for local security assessment. SecureShield does not automatically upload scanned files to external servers.

Network and Wi-Fi Information

SecureShield may access network information for Network Protection features. Depending on Android availability and permissions, this may include:

  • Current connection type
  • Wi-Fi SSID and BSSID where Android allows access
  • Wi-Fi security/encryption type
  • Network validation status
  • Captive-portal status
  • Local IP/network information
  • Gateway information
  • DNS server information
  • Private DNS status
  • VPN status
  • Metered or roaming status
  • Signal strength, frequency, band, and link speed
  • Aggregate upload/download statistics
  • Best-effort per-application network traffic totals where Android permits
  • Network-change events
  • Best-effort local-network device information

These checks are performed for security monitoring and connection-security information.

URL / Link Security Checks

SecureShield may allow users to provide or inspect a URL for local phishing-risk or suspicious-link analysis.

In the current on-device implementation, SecureShield analyzes supported URL characteristics locally and does not automatically send the URL to an external reputation service.

Usage Access and Foreground Application Information

If the user grants Android Usage Access, SecureShield may determine which application has recently been in the foreground.

This may be used for:

  • App Lock functionality
  • Real-Time Protection
  • Supported app-activity security checks
  • Background network-activity analysis

SecureShield does not use Usage Access to collect passwords, messages, keystrokes, or the private contents of other applications.

Accessibility Service

SecureShield's App Lock feature may use an Android Accessibility Service to detect when a protected application is opened so that SecureShield can display its lock screen.

The Accessibility Service is used for App Lock security functionality and is not intended to read or store typed passwords, OTP codes, private messages, or the screen contents of other applications.

App Lock Credentials

SecureShield may allow users to configure a PIN or pattern for App Lock.

App Lock secrets are stored locally using a derived cryptographic hash and salt rather than storing the original PIN or pattern as readable plaintext.

Biometric Authentication

If biometric unlocking is enabled, authentication is handled by Android's system biometric framework.

SecureShield does not receive or store the user's fingerprint, face template, or other raw biometric data.

Camera and Intruder Photo

SecureShield may request camera permission for the optional App Lock intruder-photo feature or supported camera-security checks.

If the user enables the intruder-photo feature, SecureShield may capture a photograph after repeated failed App Lock attempts.

Intruder photographs are stored locally on the device and are not automatically uploaded to SecureShield or to third parties.

Microphone Permission

Some SecureShield versions may request microphone permission for supported security or permission-state checks.

SecureShield does not use this permission to secretly record conversations or transmit microphone recordings to a server.

Location Permission

Android may require location permission for access to certain Wi-Fi information and related network-security details.

SecureShield may also inspect location/GPS settings for security-related checks.

SecureShield does not use location information to create a movement profile or automatically transmit the user's physical location to a SecureShield server.

Notifications

SecureShield may request notification permission so that it can display Real-Time Protection status, security warnings, App Lock service notifications, and other security-related alerts.

Notification permission does not by itself give SecureShield access to the private contents of other applications' notifications.

Overlay Permission

SecureShield may use Android overlay capability for supported App Lock or security functionality.

Overlay access is controlled by the user through Android Settings.

2. Real-Time Protection

SecureShield may provide an optional Real-Time Protection feature.

When enabled, a foreground service may continue running in accordance with Android rules to monitor supported security events such as device-security changes, application activity, network conditions, or other supported risk indicators.

Real-Time Protection may store recent security events locally so that they can be displayed to the user.

SecureShield does not claim to inspect information that Android does not legally or technically expose to ordinary applications.

3. Security Scan History and Reports

SecureShield may save scan results, security findings, protection scores, event history, daily or weekly scan information, and generated security reports locally on the user's device.

SecureShield may generate PDF security reports using local application data.

These reports remain local unless the user explicitly chooses to share or export them.

4. Information Sharing

SecureShield does not automatically sell, rent, or share user personal data with advertisers, data brokers, or third-party analytics companies.

SecureShield's normal scanning and analysis functions are designed to run locally on the device.

Information may leave SecureShield only when the user intentionally performs an action such as:

  • Sharing a generated security report using Android's share sheet
  • Opening content in another application
  • Opening an external website or Google Play page
  • Choosing another application as the destination for an exported file

In those cases, the selected receiving application or service processes the information according to its own privacy policy.

5. Internet Permission

SecureShield may declare Android Internet and network permissions to support network-security functionality and Android networking features.

The presence of Internet permission does not mean that SecureShield uploads locally scanned personal or sensitive data to a SecureShield server.

6. Local Storage and Security

SecureShield stores supported settings, preferences, scan history, App Lock configuration, security events, and reports locally using Android application storage.

Where supported, Android application sandboxing prevents other normal applications from directly accessing SecureShield's private application storage.

App Lock secrets are not stored as readable plaintext.

7. Data Retention

Locally stored information may remain on the device while SecureShield is installed or until the relevant data is removed.

Depending on the feature, locally retained information may include:

  • Security scan history
  • Saved security findings
  • Real-Time Protection events
  • App Lock settings
  • Trusted-app selections
  • Generated security reports
  • Optional intruder photographs

8. Deleting Data

Because SecureShield's security data is primarily stored locally, users can remove locally stored application data by using Android's app-storage controls or by uninstalling SecureShield.

Reports or files that the user has intentionally copied, exported, or shared outside SecureShield may need to be deleted separately from the destination storage location or receiving application.

10. User Choice and Permission Control

Many SecureShield features depend on permissions or special Android access that the user must explicitly enable.

Users can revoke supported permissions at any time through Android Settings. Revoking a permission may disable the related security feature.

11. No Sale of Personal Data

HI Digital Studios does not sell SecureShield user personal data.

12. No User Account Required

The current version of SecureShield does not require users to create a SecureShield online account in order to use its core local security functions.

13. Third-Party Services and Android Platform

SecureShield relies on Android system APIs and may open Android Settings, Google Play, or another user-selected application.

Google Play, Android, device manufacturers, and third-party applications may independently process information according to their own privacy policies. Such processing is outside SecureShield's local security-scanning system.

14. Children's Privacy

SecureShield is a general Android security utility and is not specifically designed as a children's application.

This Privacy Policy may be updated if SecureShield's functionality, permissions, data-handling practices, or legal requirements materially change.

The latest version will be published at this same public Privacy Policy URL.
